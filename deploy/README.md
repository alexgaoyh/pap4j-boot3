# 发布到 Maven Central（一个模块一条命令）

以前一次性 deploy 会把所有模块打成一个 1.6G 的 bundle，Central 的上传接口等不及，直接断连。
现在改成一个模块一条 `mvn deploy`，每次只传几十 M，稳得多。

跑之前就两件事：

- **先 git commit**，`git-commit-id` 的 `validateRevision` 会拦未提交的改动（不想提交就每条加 `-Dgit-commit-id-maven-plugin.skip=true`）。
- **gpg 用 `D:/GnuPG/bin/gpg.exe`**，Git Bash 自带的那个读不到 `%APPDATA%\gnupg` 的密钥，会报 `can't connect to the gpg-agent`。命令里已经带上了。

另外顺序不能乱：父 pom 必须先发布，否则模块校验会报 `License/SCM/URL/Developers missing`、`Dependency version missing`。

## 1. 父 pom（发新版本时跑，0.0.5 已经发过了，可以跳过）

```bash
rm -rf target/central-staging target/central-deferred target/central-publishing; mvn -B -ntp clean deploy -pl . -Dmaven.skipTests=true -Dmaven-checkstyle-plugin.skip=true -Ddependency-check-maven.skip=true -DautoPublish=true -DwaitUntil=VALIDATED -DignorePublishedComponents=true -Dgpg.executable=D:/GnuPG/bin/gpg.exe
rm -rf target/central-staging target/central-deferred target/central-publishing; mvn -B -ntp clean deploy -pl pap4j-common,pap4j-boot3-starters -Dmaven.skipTests=true -Dmaven-checkstyle-plugin.skip=true -Ddependency-check-maven.skip=true -DautoPublish=true -DwaitUntil=VALIDATED -DignorePublishedComponents=true -Dgpg.executable=D:/GnuPG/bin/gpg.exe
```
