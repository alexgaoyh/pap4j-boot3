# 📢 grill-me 技能 SOP (苏格拉底式架构方案反向质询)

## 📌 触发机制

- **🤖 自动触发**：当意图触发 `AI.md` 中的 **`[Plan]` 强阻断条件**（跨模块调用协议变更、底层高并发组件重构、多模块联动 ≥3 个 `src/main/java` 源文件、依赖与配置变更、持久层与事务红线违规、公共 API 签名行为变更）时。
- **💬 显式触发**：当开发者输入 `grill-me`、`“质询架构方案”` 或 `“对当前设计发起质询”` 时。

---

## 🛠️ 执行流程 (Execution Steps)

### 步骤 1：上下文与代码自检 (Analysis)
1. 识别改动物理边界与影响的子模块（如 `pap4j-common-file`, `pap4j-boot3-starters-logback` 等）。
2. 核查 `guard.md` 中的硬核禁令（JPA 关联映射注解禁令、`pap4j-common` 公共 API 变更限制、并发锁规范等）。

### 步骤 2：暂停编辑与质询构建 (Socratic Interrogation)
在进行任何 `[Edit]` 操作前，AI **必须暂停代码编辑**，并主动构建 **3~5 个硬核反向质询问题**：
1. **高并发与死锁/竞态**：在高并发场景下是否存在锁粒度过大、死锁风险或线程池耗尽隐患？
2. **极值与边界条件**：空值、大报文、超长字符串、并发读写碰撞等极端边界情况如何防御？
3. **缓存与穿透/击穿**：若涉及缓存，是否有击穿、雪崩或数据不一致防范措施？
4. **幂等性与降级容灾**：接口重试是否具备幂等保障？网络抖动或下游服务异常时是否有优雅降级？
5. **API 向后兼容性**：若涉及 `pap4j-common`，修改是否破坏已有下游模块的二进制/源码兼容性？

### 步骤 3：与开发者互动对齐 (Alignment)
输出格式如下：

```markdown
### 🛑 [Plan / grill-me] 苏格拉底式反向质询

在开始编辑代码前，针对本次改动提出以下关键设计质询，请确认或补充指导：

1. **[并发/死锁]**: ...
2. **[边界/极值]**: ...
3. **[缓存/一致性]**: ...
4. **[API 兼容性]**: ...

在收到您的反馈与明确指导前，AI 将保持在 [Plan] 状态，暂停任何 [Edit] 操作。
```

### 步骤 4：方案修正与进入 `[Edit]`
收到开发者回答后，AI 调整设计方案，经开发者同意后进入 `[Edit]` 编码阶段。
