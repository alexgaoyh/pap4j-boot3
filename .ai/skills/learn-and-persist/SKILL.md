# 📝 learn-and-persist 技能 SOP (技能沉淀与自适应演进)

## 📌 触发机制
- **🤖 自动触发**：
  - 当攻克了高难度的环境报错（如 Windows 乱码、Maven 构建冲突、K8s 探针异常）。
  - 当重构了复杂的业务模型，总结出可复用的通用代码模板或重构 SOP 时。
  - 当用户纠正了 AI 代理的某种特定代码实现偏好，需要对后续开发进行硬性规约时。
- **💬 显式触发**：当开发者或 AI 自身发出 `“沉淀当前经验”`、`“持久化为技能”` 或 `learn-and-persist` 时。

---

## 🛠️ 执行流程 (Execution Steps)

### 步骤 1：经验提取与归档定位
1. 判断沉淀的经验类型，选择最佳物理承载位置：
   - **通用开发/重构 SOP**：在 `.ai/skills/` 下新建一个专属技能目录并撰写 `SKILL.md`（例如 `.ai/skills/custom-integration/SKILL.md`）。
   - **局部排错与踩坑库**：若是特定的局部排错技巧，追加写入到 `.ai/diagnostics/troubleshooting.md` 中。
   - **架构红线/硬约束**：若是对编码或技术栈的硬性禁令，追加或修改至 `.ai/guard.md`。

### 步骤 2：撰写标准化 Skill 文件 (SKILL.md 模板)
新创建的技能文件必须包含标准的 YAML Frontmatter，基本模板如下：
```markdown
---
name: 技能小写短命名 (如 my-new-utility)
description: [分类/场景] 简短描述该技能的作用与触发条件。
globs: "*"
---

# 📝 技能命名 技能 SOP

## 📌 触发机制
- 描述在什么情况下应该读取并应用本技能（含自动触发的关键词）。

## 🛠️ 执行流程
- 详细步骤列表 (Step 1, Step 2...)。

## ⚡ 命令行与规范示例
- 列出执行该技能时推荐使用的标准命令（Git Bash / PowerShell 双环境兼容）以及正确/错误的代码反模式。
```

### 步骤 3：索引更新与通知
- 在任务的最终回复中，AI 代理必须主动向用户报告：“已将本次解决的 `[具体问题]` 沉淀为 `.ai/skills/xxxx/SKILL.md` 技能，下一次交互我将自动提取并运用该技能，避免重复踩坑。”
